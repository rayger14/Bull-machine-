# Trader teachings transferred to four historical setups

## Question and scope

Can an agent interpret the actual rules and multi-timeframe price structure, and
does adding the saved trader-note excerpts improve that interpretation? This
follows the [narrow teaching/code comprehension pass](trader_teaching_comprehension_2026_09_11.md).
It is not a test of all17 archetypes or a live trading authorization.

The [registered protocol](../superpowers/specs/2026-09-11-teaching-market-transfer.md)
was committed before one guarded August2026 reconstruction. It selected the first
qualifying hourly LC and minute sweep/reclaim event in each half-month, without
looking at outcomes. Exact30day seed starts July2; the saved Binance minute
archive supplies every price layer and hypothetical execution. All17 native
signal archetypes ran, but no native book, allocation or live order ran. The
minute detector is separate research code, not LC at a faster clock.

Each of four cases has two fresh isolated assessors. Shared evidence comprises
completed1m/5m/15m/1h/4h/daily candles, pre-setup fixed parents, track-specific code
and H1/H2/H3 project contracts. ON adds seven unchanged secondary teaching-note
excerpts; OFF does not. OFF still has teaching-derived language in the shared
project contracts, so this is an incremental excerpt comparison, not all trader
knowledge versus none. Equal output limits do not certify equal compute or input
tokens. No case repeats or response retries were allowed.

The corpus is locally attributed, not independently authenticated original
teacher material. Conflicting HTF-size accounts were preserved. Numerical range,
pivot, compression and location rules remain project hypotheses. Neither agent
was given future prices, prior assessment verdicts or the paired answer.

## Quant-guided next step

No additional market assessor batch was authorized by the guide at this point.
First, build the [small deterministic evidence guard](../superpowers/specs/2026-09-11-assessment-evidence-guard.md):
bounded auditable packet delivery, precomputed indicative arithmetic and exact
evidence paths, plus one-case-only future factual reviewers until reviews lock.
Transport records are caller attestations, not proof the model read every byte;
path existence is not citation entailment.

The new `scripts/research/assessment_evidence_guard.py` is a standalone pure
helper, with39 focused tests and no dependency, model/API, file/network I/O or
live integration. `build_envelope` creates canonical JSON chunks, a section
inventory, byte/hash records and deterministic indicative economics.
`validate_delivery` checks a caller-supplied complete ordered text receipt against
the original packet; `resolve_evidence` resolves an exact typed path and returns
a detached value. Missing/changed/reordered/truncated chunks, cross-case IDs,
invalid numbers and nonexistent or wrongly typed paths fail the relevant boundary checks.

Root also used all eight existing packets as **no-model fixtures**: each complete
in-memory roundtrip passes and each dropped-final-chunk control fails. Canonical
packets are21137–27949bytes, six or seven4096byte chunks. T04 indicative breakeven
is calculated63099.92916 instead of asking a model to perform that arithmetic.
These are not actual tool-delivery receipts, no historic response was repaired,
and the helper cannot certify causal truth, natural-language entailment, source
authenticity or reviewer isolation. Actual transport capture and future isolated
review routing still require integration and a separately frozen delivery smoke
test. No additional market assessment was run for this safeguard.

Independent task review found and corrected a lossy large-integer-to-float input
conversion and a missing independent hash-test expectation. Inputs that cannot
