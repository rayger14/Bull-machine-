# Teaching-to-code implementation and prior-test coverage

## Which source-derived components exist, and which actual path uses them?

### Takeaway
The repository already implements most ingredient families, but only a subset is active in the champion paper path. The active chain is Coinbase closed 1H candle → `LiveFeatureComputer` → `V11ShadowRunner` → `IsolatedArchetypeEngine` → `ArchetypeInstance`/`StructuralChecker`; the systemd service explicitly selects `configs/champion_paper.json`. Rich detector objects generally do not survive this chain as stable setup objects.

### Cited Findings

## Where does original knowledge become a scalar or bypassed condition?

### Takeaway
The main fidelity loss occurs between detector output and archetype identity: objects with bounds, direction, timestamps and lifecycle become flags or unsigned fusion scores; missing inputs can be skipped, and some structural exceptions fail open.

### Cited Findings
- Live preserves SMC object lists only long enough to derive `fusion_smc`, BOS flags and FVG-present flags ([bin/live/live_feature_computer.py:1249](../../bin/live/live_feature_computer.py#L1249), [bin/live/live_feature_computer.py:1274](../../bin/live/live_feature_computer.py#L1274), [bin/live/live_feature_computer.py:1289](../../bin/live/live_feature_computer.py#L1289)). OB zone IDs/bounds and sweep trigger levels are not placed in the feature row, although `SMCSignal` contains them ([engine/smc/smc_engine.py:19](../../engine/smc/smc_engine.py#L19)).
- The SMC scalar itself is an unsigned maximum-side component count divided by four ([engine/smc/smc_engine.py:199](../../engine/smc/smc_engine.py#L199), [engine/smc/smc_engine.py:211](../../engine/smc/smc_engine.py#L211)). Live 4H fusion similarly uses `bullish_BOS or bearish_BOS`, then copies that value into daily fusion ([bin/live/live_feature_computer.py:1487](../../bin/live/live_feature_computer.py#L1487), [bin/live/live_feature_computer.py:1492](../../bin/live/live_feature_computer.py#L1492)). TWT treats either high or low 4H fusion as trend permission when above-EMA is absent/false ([engine/archetypes/logic.py:779](../../engine/archetypes/logic.py#L779)).
- The rich level columns are computed live, but none is an active champion entry gate/identity. Only an off-by-default exit ladder references prior-day/swing/round levels ([engine/archetypes/exit_logic.py:1045](../../engine/archetypes/exit_logic.py#L1045)). Thus existing level provenance currently bypasses the named sweep/OB/FVG entries.
- Gate evaluation can treat missing values as pass and remove skipped gates from the denominator; soft failures only shrink fusion ([engine/archetypes/archetype_instance.py:663](../../engine/archetypes/archetype_instance.py#L663), [engine/archetypes/archetype_instance.py:765](../../engine/archetypes/archetype_instance.py#L765)). Structural-check exceptions explicitly return pass ([engine/archetypes/structural_check.py:175](../../engine/archetypes/structural_check.py#L175)). Neutral archetypes cannot emit at all in the generic detector ([engine/archetypes/archetype_instance.py:877](../../engine/archetypes/archetype_instance.py#L877)).

### Inferences
- Fusion can rank context but cannot prove setup identity. Direction agreement, “same zone,” first retest, reclaim, expiry and invalidation require IDs and event transitions; adding another score would preserve the same failure mode.

### Gaps
- This was a source trace, not runtime provenance certification. It does not prove every live feature was observed rather than defaulted on any historical/server bar.

## Is the remaining gap missing knowledge, missing provenance, or unwired/degraded implementation—and what must not be repeated?

### Takeaway
All three exist. The dominant near-term gap is unwired object lineage plus causal input status; exact teacher-authenticated definitions remain missing for several setups. Prior research already rejects simply adding generic level, parent, room or wait-confirmation gates.

### Cited Findings
- **Missing knowledge/definition:** OBR lacks a direction-correct OB lifecycle; FVG lacks same-event break/gap binding; range/neutral archetypes lack executable side/boundaries; R3's six-bar/quarter-width/retest constants are explicitly project hypotheses, not recovered teacher rules ([docs/knowledge/archetype_repair_scorecard_2026_09_30.md:60](../../docs/knowledge/archetype_repair_scorecard_2026_09_30.md#L60); [docs/superpowers/specs/2026-09-30-archetype-repair-discovery-design.md:131](../../docs/superpowers/specs/2026-09-30-archetype-repair-discovery-design.md#L131)).
- **Missing provenance:** selected V23 fields include constant `funding_Z`, late-disappearing absorption/effort-result, partial breadth coverage and 61 missing hours; variability alone is not causal/live parity ([docs/knowledge/archetype_repair_scorecard_2026_09_30.md:160](../../docs/knowledge/archetype_repair_scorecard_2026_09_30.md#L160)). Existing parent code solves a narrower provenance problem: hash-bound sources, explicit `available_at`, stable pivot/version/lineage IDs and append-only transitions ([scripts/research/causal_parent_ledger.py:1](../../scripts/research/causal_parent_ledger.py#L1), [scripts/research/causal_parent_ledger.py:255](../../scripts/research/causal_parent_ledger.py#L255)).
