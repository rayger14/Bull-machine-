Scope: bounded read-only audit of branch `quant/archetype-evidence-audit` at `85923a4`. The existing Graphify graph oriented discovery, but every decisive claim below was checked in the selected source files. This is not a server fingerprint, replay, test, backtest, profit attribution, or certification of any trader's complete corpus.

## Is Wyckoff actually the backbone of the live 17?

### Takeaway

Wyckoff is genuinely active, not absent: the selected producer computes hierarchical 1D→4H→1H events and directional scores, every enabled YAML gives the Wyckoff domain a positive fusion weight, and C-accumulation can increase long size. But no executable archetype identity hard-requires a named Wyckoff range/phase sequence. In the current book Wyckoff is shared, direction-aware **context**, usually flattened to carried scalar maxima; it is not the mandatory setup backbone implied by the stronger hypothesis.

### Cited Findings

The verified immediate enabled roster is 17: 14 long, one short and two neutral; seven use hard YAML gate mode and ten soft. The three `*_example.yaml` files are not enabled roster members.

- Live Wyckoff detects SC/BC/AR/AS/ST/SOS/SOW/Spring/UT/UTAD/LPS/LPSY, with daily and 4H context passed downward ([bin/live/live_feature_computer.py:1604](../../bin/live/live_feature_computer.py#L1604), [bin/live/live_feature_computer.py:1796](../../bin/live/live_feature_computer.py#L1796)). - Fusion is not merely logged. It must first clear each YAML's inner `fusion_threshold` in the default `signal_mode='fusion'` ([engine/archetypes/archetype_instance.py:840](../../engine/archetypes/archetype_instance.py#L840), [engine/integrations/isolated_archetype_engine.py:679](../../engine/integrations/isolated_archetype_engine.py#L679)). The runner then computes a second dynamic threshold. `bypass_threshold=true` bypasses only that **outer** threshold ([configs/champion_paper.json:124](../../configs/champion_paper.json#L124), [bin/live/v11_shadow_runner.py:1168](../../bin/live/v11_shadow_runner.py#L1168)). Bypass also skips position/spacing/allocation filters, while the engine's earlier best-per-direction dedup remains ([bin/live/v11_shadow_runner.py:1269](../../bin/live/v11_shadow_runner.py#L1269), [engine/integrations/isolated_archetype_engine.py:773](../../engine/integrations/isolated_archetype_engine.py#L773)).
- Gate absence is material: `skip/pass` missing values are removed from the denominator; hard mode blocks failures and soft mode scales fusion ([engine/archetypes/archetype_instance.py:674](../../engine/archetypes/archetype_instance.py#L674), [engine/archetypes/archetype_instance.py:825](../../engine/archetypes/archetype_instance.py#L825)). Structural exceptions fail open ([engine/archetypes/structural_check.py:175](../../engine/archetypes/structural_check.py#L175)). C-accumulation is a separate active 1.25× size boost for any long, not entry identity ([bin/live/v11_shadow_runner.py:1454](../../bin/live/v11_shadow_runner.py#L1454)).
- Source fidelity must stay versioned. Richard Wyckoff's 1910 text supports supply/demand/volume, accumulation→markup→distribution and waiting for a narrow-range breakout ([scan](https://archive.org/details/studiesintaperea00wyckrich), [OCR](https://archive.org/stream/studiesintaperea00wyckrich/studiesintaperea00wyckrich_djvu.txt)); the inspected book does not establish the later named spring/A–E schema. A–E, spring/test/LPS/SOS are supported by a [modern Wyckoff-school synthesis](https://www.wyckoffanalytics.com/wyckoff-method/), not proof of Richard's exact terminology. The project's numeric rules remain translations.

### Inferences

The accurate current description is “17 project-defined identities sharing optional Wyckoff context,” not “17 faithful Wyckoff setups.” That does not imply funding/OI setups should be forced into Wyckoff. Making range/sequence lineage a future common architecture is a design hypothesis, distinct from what the named authors actually taught.

### Gaps

This pass did not certify which fallback/default was present on any historical or server bar. No observed code defect is claimed to explain historical losses.

## Are hidden Fibonacci price/time zones and Gann timing active and faithful?

### Takeaway

Coarse Fibonacci price/time features are active, but only two archetypes directly consume temporal fields. The champion path has no active implementation of the inspected hidden extensions or Gann calendar/anniversary timing. Several richer modules are alternate/dormant. “Present in repository” and “permits an entry” are therefore very different claims.

The 17 identities are useful project heuristics, but most detect a current state—wick, RSI, funding, FVG flag—rather than an identified setup progressing through location, trigger, expiry and invalidation. ### Inferences

Revise the combined hypothesis to: **17 project-defined entry heuristics with shared optional Wyckoff scalar context and common ATR/central management; two direct temporal consumers; no active, faithful hidden-Fib-extension or Gann-calendar implementation.** Preserve a future design hypothesis—identified parent range/level → ordered event/reclaim/break → causal confirmation → expiry/invalidation → destination/management—but do not call that common ontology an authenticated all-trader system.

Finite priorities separate engineering from economics:

1. **Demonstrated semantic/representation contradictions:** `_bars_since_pivot` chooses the oldest qualifying pivot despite claiming the last; the shifted Fib confirmation mask is used to read confirmation-bar price and start the time count rather than the original extremum; rolling-window fallbacks make advertised higher Fib/Gann counts unreachable; the live temporal producer discards the batch master score; and the runner builds central defaults without loading per-YAML exit blocks. Price-mod-9 and rolling-low age are also not the calendar timing named in the inspected Gann source. These observations justify specification review, but do not by themselves identify the correct replacement or prove PnL impact.
2. **Proposed design/policy contracts, not proven defects or recovered author rules:** decide whether to preserve `available_at`, parent range/level/event IDs and direction through feature→identity; whether Fib extensions need an active-leg and zone lifecycle; whether neutral archetypes need executable sides; whether OI needs a mandatory divergence identity; whether structural errors should fail closed/unknown; and which management/invalidation version should govern. Each requires an explicit product/research contract and causal testing rather than post-hoc attribution to a trader.
3. **Economic hypotheses requiring isolated causal testing afterward:** whether Wyckoff-sequence gating, Fib price/time location, or source-versioned Gann calendar anchors add expectancy; and whether proposed R1/R3 distinctions help. R1 and R3 remain proposals, R2 remains parked, and prior LC no-promotion evidence remains binding ([archetype scorecard:198](../../docs/knowledge/archetype_repair_scorecard_2026_09_30.md#L198)). Source fidelity alone is not profit.

### Gaps

Exact author attribution is unknown for most archetype names and every project threshold unless a source above explicitly supports the concept. No canonical teacher taxonomy of 17 was found or inferred, and no setup is certified merely because its label resembles a teaching.
