# Bull Machine — agent startup and continuity

For development/controller sessions, first read `PROJECT.md`. Outcome-hidden
market assessors must instead follow their restricted packet-only instructions
and must not load project history. Development sessions then read the newest
dated overrides in `docs/knowledge/MEMORY.md` and the active spec/plan linked by
the handoff. Verify branch, git status and recent commits before resuming work.
Do not assume this chat or another CLI's hidden memory is available.

`PROJECT.md` is the short current-state entrypoint. Dated experiment
reports are evidence; hypotheses and old performance headlines are not current
certification. `CLAUDE.md` and `docs/knowledge/STATE_OF_THE_ENGINE.md` contain older
architecture/performance descriptions; newer explicit corrections take precedence.

At every meaningful checkpoint or handoff, update `PROJECT.md` with what
actually finished, verification evidence, work still running, next action and
local-only dependencies. Do not mark work done because it was planned or an
agent reported completion without verification. Preserve historical reports.

Current work is offline research on a dedicated quant branch. Preserve all17
archetypes and frozen experiment artifacts; no production/live orders, config,
fusion changes, push, PR or paid fine-tuning without applicable user authority.
Keep developer project memory separate from outcome-hidden market-role packets.
Never give test assessors this handoff, project MEMORY, or known-outcome reports.

For another CLI that does not automatically read AGENTS.md, explicitly instruct
it to read `PROJECT.md` before doing anything else. This is file-backed
continuity, not shared model weights or a guarantee that every tool auto-loads it.
